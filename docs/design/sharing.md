# 기록 공유 설계 (초안)

상태: 초안. 호스팅 플랫폼은 정하지 않았다. 이 문서는 어느 플랫폼에서든 같게 유지할 것만 정한다.

## 왜

- 지금은 기록이 그 브라우저에만 있다. 다른 사람에게 보여 주려면 백업 파일을 주고받아야 한다.
- 같은 경기를 여러 사람이 기록하고 합치려면(비교·합의 기능) 기록이 한곳에 모여야 한다.
- 링크를 메신저나 SNS에 붙였을 때 그 경기의 날짜, 구장, 팀, 스코어가 미리보기로 나와야 한다. 크롤러는 JS를 실행하지 않으므로 서버가 경기마다 다른 HTML과 이미지를 줘야 한다.

## 원칙

- 앱은 서버 없이도 끝까지 동작한다. 공유는 선택 기능이다.
- 앱(정적 파일)과 공유 서버는 분리한다. 앱은 지금처럼 정적 호스팅에 두고, 공유 링크·API·미리보기만 서버가 맡는다.
- 서버에 올라가는 것은 사용자가 공유를 누른 경기의 기록뿐이다.
- 공유된 기록은 링크를 아는 누구나 볼 수 있다. 앱에서 이를 공유 전에 밝힌다.
- KBO 경기는 기록자가 직접 보고 입력한 것만 올린다. 중계 데이터를 옮겨 적은 기록은 받지 않는다는 점을 안내한다.
- 서버 코드도 AGPL-3.0-or-later로 공개한다.

## 단계

| 단계 | 내용 | 계정 |
| --- | --- | --- |
| B-1 링크 공유 | 경기 하나를 그 시점 그대로(스냅샷) 올리고 링크를 받는다. 링크를 연 사람은 읽기 전용으로 보고 내 기록으로 가져올 수 있다. 링크 미리보기는 경기마다 다르다 | 없음 |
| B-2 같은 경기 묶기 | 같은 경기로 보이는 공유 기록을 묶고, 서버에서 합의 기록을 만든다 | 없음(삭제 키로 관리) |
| B-3 기록자와 신뢰도 | 기록자별 신뢰도, 분쟁 처리, 합의 기록 고치기 | 필요 |

## 스냅샷 형식 (B-1)

백업 파일과 같은 이벤트 로그를 경기 하나로 담는다. 서버는 이 내용을 바꾸지 않는다. 고치면 새 스냅샷이 된다.

```json
{
  "app": "openScoreBook",
  "kind": "share",
  "version": 1,
  "createdAt": "2026-11-16T12:00:00.000Z",
  "summary": {
    "date": "2026-04-04", "stadium": "잠실",
    "away": "청룡", "home": "백호", "score": [4, 5],
    "innings": { "away": ["0","1","0","0","0","2","0","1","0"], "home": ["0","0","0","1","0","0","0","4"] },
    "status": "final", "inning": 9, "top": false
  },
  "events": [ { "id": "...", "kind": "m.setup", "at": 0, "setup": { } } ]
}
```

- `events`: 그 경기의 이벤트. `gameId`와 `seq`는 빼고 올린다(받는 쪽이 새로 붙인다).
- `summary`: 미리보기와 목록에 쓰는 요약. 서버는 이벤트를 다시 계산해 이 값과 맞는지 확인한 뒤에만 받는다(엔진이 WASM이라 서버에서도 돈다). 맞지 않으면 거부한다.
- `status`: `final`(경기 끝), `live`(진행 중). 진행 중 경기는 이닝과 초말을 함께 둔다.

## 링크와 API

| 경로 | 하는 일 |
| --- | --- |
| `POST /api/share` | 스냅샷을 받아 검사하고 저장한다. 응답: `{ id, url, deleteKey }` |
| `GET /api/share/:id` | 스냅샷 JSON |
| `DELETE /api/share/:id` | `deleteKey`가 맞으면 삭제한다 |
| `GET /g/:id` | 사람에게는 앱으로 넘긴다(`앱주소/#share=:id`). HTML에는 그 경기의 OG 태그를 넣는다 |
| `GET /g/:id/card.png` | 1200×630 스코어 카드. `app/src/lib/card.ts`가 만드는 SVG를 PNG로 바꾼 것 |

- `id`: 추측하기 어려운 무작위 값(예: 10자 이상 base62). 순번은 쓰지 않는다.
- `deleteKey`: 공유한 브라우저에만 저장한다. 계정이 없는 단계에서 지울 수 있는 유일한 방법이다.
- 앱은 `#share=:id`로 열리면 스냅샷을 받아 읽기 전용으로 보여 주고 `내 기록으로 가져오기`를 제공한다.

## 동적 미리보기

`GET /g/:id`의 HTML에 넣는 값:

- `og:title`: `청룡 4 : 5 백호`
- `og:description`: `2026-04-04 · 잠실 · 경기 종료` (진행 중이면 `9회말 진행 중`)
- `og:image`: `/g/:id/card.png`
- `og:url`: `/g/:id`
- `twitter:card`: `summary_large_image`

카드 이미지는 앱과 서버가 같은 코드(`card.ts`)로 만든다. 앱에서는 SVG를 그대로 쓰거나 캔버스로 PNG를 만들어 공유 메뉴로 보낼 수 있다. 서버에서는 SVG를 PNG로 바꾸는 라이브러리(예: resvg)를 쓴다. 이때 한글 글꼴 파일을 함께 둬야 한다.

## 남용 막기 (B-1)

- 스냅샷 크기 제한(예: 1MB)과 IP별 요청 횟수 제한.
- 엔진 검산과 요약 일치 확인을 통과한 것만 저장.
- 신고와 관리자 삭제 경로.

## 개인정보

- 사회인·아마추어 기록에는 실명이 들어간다. 공유 전에 "링크를 아는 누구나 볼 수 있다"를 확인받는다.
- 공유한 사람은 `deleteKey`로 언제든 지울 수 있다. 선수 본인의 삭제 요청을 받을 연락처를 둔다.
- 미성년자(고교 이하) 기록은 B-3 전까지 이름 대신 등번호만 쓰도록 안내하는 것을 검토한다.

## 플랫폼 선택 시 확인할 것

- 정적 파일과 별개로 작은 함수(요청마다 실행)를 돌릴 수 있는가.
- 객체 저장소(스냅샷 JSON)와 간단한 키-값 또는 SQL(목록, B-2 묶기)이 있는가.
- WASM 실행(엔진 검산, SVG→PNG 변환)이 되는가.
- 무료 범위, 요청 제한, 데이터 위치, 운영자가 직접 지울 수 있는가.

후보: Cloudflare Workers + R2 + D1, Vercel Functions + Blob, Supabase(Postgres + Storage + Edge Functions), 작은 VPS.

## 정하지 않은 것

- 호스팅 플랫폼과 도메인.
- 공유 데이터의 라이선스(예: CC BY-SA 4.0). B-2 전에 정한다.
- B-2에서 "같은 경기"를 판단하는 기준(날짜·구장·팀만으로 충분한지, 더블헤더 번호).
